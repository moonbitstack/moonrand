The generator contract lives in the contract subpackage so the root package and the algorithm subpackages can both use it without a circular import. To name the traits, import @moonrand/contract (Rng, Secure, Seeded); the root package adds the convenience names below.

The default generator is ChaCha12 (see StdRng). Two ways in: seeded is pure and reproduces a stream from a seed you supply; @auto.rng() asks the platform through moonseed for a seed no one can predict or replay. Everything else in the library is pure, so a seeded run repeats exactly.

The default generator: ChaCha12. Change this one line to change the whole library's default algorithm.

Rng

trait
pub(open) trait Rng

The contract every generator satisfies: produce uniform machine words. The algorithms in subpackages implement the one required method next_u64; the other two are shared defaults. The sampling and distribution functions in moonrand are generic over any Rng.

Methods take Self by value and keep their state in interior-mutable fields (Array buffers and priv mut scalars), so a draw advances the caller's generator without a mutable reference. That is also why a generator is a handle rather than a value: let b = a copies the handle and shares its buffer, so both draws advance one state. For two independent streams, build two generators from the seed.

One call, seeded from the platform through moonseed.

functions

pub fn rng() -> @moonrand.StdRng raise @moonseed.Unavailable

A StdRng seeded from the platform's entropy: 32 bytes asked of @system.source through moonseed, then handed to @moonrand.seeded.

This is the only place the library touches the platform. It fails with @moonseed.Unavailable when there is no entropy source or when reading it fails; there is no fallback to a fixed or clock-derived seed, because a silent fallback would hand out a generator that looks random and is not.

let r = @auto.rng() catch { _ => return }
let x = @moonrand.random(r)
assert_true(x >= 0.0 && x < 1.0)
}

Arithmetic wider than a machine word, and the one way a byte seed becomes state words. Both are shared: 128-bit generators need the high half of a 64-bit product, and every generator needs the same expansion so the same seed means the same stream in every subpackage.

The SplitMix64 finalizer: three xorshifts and two odd multipliers, a bijection on 64-bit words.

pub fn seed_words(seed : BytesView, n : Int32) -> FixedArray[UInt64]

n state words from seed. The seed is read eight bytes at a time, little endian, mixed into a SplitMix64 counter, and the counter is run forward — so every byte of the seed counts, and a short seed is the same as itself with zero bytes appended.

The construction here is the one this library defines — the counter and the key are the published shape, the round function is written out below — and the tests replay what scripts/gen_vectors.go produces from the same definition. It is not claimed to match the author's own constants word for word.
