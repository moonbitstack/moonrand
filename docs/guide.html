guide

From a seed to a distributionten steps

Every block below was run against this version, and the line under it is what it printed. Read it in order, or take the section you came for.

step 01

it starts with a seedinstall

Add the module and the generator comes with it. There is nothing to configure: seeded takes any bytes and gives back a generator, and every draw after that is a function that takes the generator first.

Thirty-two bytes fix the whole stream. Where they come from is your business — a constant, a file, a hash, a row id. The same bytes always draw the same numbers, which is what makes a run that went wrong replayable.

step 02

the seed decides the streamseed

A seed is not a number that picks a starting point; it is the whole state. Two generators seeded alike are the same generator, and one changed byte is a different stream from the first draw — not a related one that drifts.

randbytes writes the stream out as bytes, which is the plainest way to see that. Every backend — native, JS, wasm, wasm-gc — writes the same eight bytes here.

step 03

a generator is a handlehandle

There is no global generator and no thread-local one: a generator carries its own state, and the functions that draw are generic over it. Two generators built from the same seed walk the same numbers, side by side, without touching each other.

The state itself lives in a buffer the handle points at, so let b = a gives you a second name for one state rather than a second stream. Seed another generator when you want two streams to be independent — or use jump, below, to move one of them far away.

step 04

when the algorithm mattersalgorithms

The default is ChaCha12, and most code should keep it. When a published algorithm is the point — reproducing someone else's stream, matching a paper, fitting a hardware budget — pick the type out of the subpackage that holds that family. Every one of them satisfies the same contract, so randint and the rest do not change.

The same seed across three families gives three different numbers, and the same family on another machine gives the same one.

step 05

integers, without a thumb on the scaleintegers

randint takes both ends, randrange leaves the right one out and allows a start and a step, and getrandbits returns the low bits of a word. None of them takes a remainder: a draw outside the range is rejected and drawn again, so no value is more likely than another however ragged the range is.

An inverted range is answered, not punished — high below low returns low — while a range with no integers in it aborts, because there is no honest number to return.

step 06

choosing from a collectioncollections

Five functions cover the deck: choice takes one, choices takes several with replacement, sample takes several without, shuffle reorders in place, and permutation hands back the order as indices.

Give choices weights and the draws follow them. Give sample weights and each place is filled from what is still left, in proportion — a heavier element tends to come out earlier, and nothing repeats.

step 07

the shapesdistributions

One draw each, over the same generator, named as Python's random names them. Gamma, beta, chi-squared, Student's t and Fisher's F are one family: each is built from a gamma or a normal draw by its own definition, so a beta is two gammas and a t is a normal over a chi-squared.

gauss and normalvariate are two algorithms, not two spellings — Box-Muller against ratio of uniforms. A run that swaps one for the other does not reproduce, and neither caches a spare draw, so the stream stays in step with the calls you make.

step 08

jumping aheadjumping

Counter-based generators can be moved instead of drawn. advance adds to the counter, and jump sends a shift-register generator a fixed distance along its own cycle by the polynomial its authors published — two hundred bits ahead for long_jump. Both cost a fixed handful of operations, however far they move.

That is how one seed becomes many streams: seed once, then jump each worker into its own stretch of the cycle, where the stretches do not overlap.

step 09

when it must not repeatentropy

Everything so far is reproducible on purpose. For a run that should not repeat — a session id, a jitter, a salt — ask the platform for the seed instead: @auto.rng() takes thirty-two bytes from the operating system through moonseed and hands them to the same generator.

It raises when there is no entropy source, rather than falling back to a clock or a constant. A machine that cannot give you randomness is a thing you want to hear about. On wasm-gc, where the host decides whether a source exists, that error is expected.

step 10

writing your ownown

The contract is three methods, and only one of them has to be written: next_u64. next_u32 and fill follow from it, and so does everything above — the sampling, the distributions, the lot.

State lives in the type, so a struct with a mut field is enough. Add impl Seeded for Counter to rebuild it from a seed, and impl Secure only when the output is fit for cryptography: Philox and PCG pass statistical tests and are not.
